畫面的看法

  • 外框・指示燈 灰色：已停止／未設定
  • 綠色：執行中（一般權限）
  • 橘色：執行中（系統管理員權限）
  • 紅色：設定為「以系統管理員啟動」，卻以一般權限執行中
  • OBS 圖塊的外框：淺藍 = 未直播／紅色 = 直播中／紫色 = 僅錄影。中間的數字是傳送量
  • 閃爍橘色的圖塊：啟動序列下一個要啟動的應用程式
  • 圖塊右上：ADMIN／USER／STANDBY（已停止）／NO PATH（未設定）
  • GROUP（直向排列；LINEAR 尚未實作）：用滾輪／▲▼ 轉動圓環。相同分類的應用程式會疊在一起，滑鼠移上去時往旁邊展開。Shift+滾輪／傾斜滾輪可橫向轉動同一列

顯示模式（LINEAR／GROUP）、橫向・縱向上限、序列完成後的動作（最小化／隱藏）可在設定的「一般」中變更。 隱藏的啟動器可從系統匣圖示還原。

平常的顯示可選擇「只顯示圖示（滑鼠移上去時展開）」或「永遠展開」（設定的「一般」，或空白處的右鍵選單）。 D&D 模式中與啟動序列執行中會保持展開。

大小可在啟動器上用 Ctrl+滑鼠滾輪，或設定中的「大小」變更。

左鍵點圖示 = 啟動（已在執行中則不動作）／右鍵 = 選擇權限後啟動。
在啟動器空白處按右鍵可開啟選單（位置・序列・設定・結束）。

以系統管理員權限執行 OBS 的優點

  • OBS 可以提高自己的 GPU 優先順序，在遊戲讓 GPU 負載很高時，比較不容易出現「算繪延遲／編碼延遲」。
  • 可以用遊戲擷取／視窗擷取來擷取以系統管理員權限執行的遊戲或應用程式。
  • 部分有反作弊的遊戲，若不是系統管理員權限可能無法擷取。

缺點

  • 無法再從檔案總管拖放。（見下方）
  • 每次啟動都會出現 UAC 確認。若由開機啟動，登入後會馬上出現 UAC。
  • OBS 裡的瀏覽器來源・外掛・腳本也全都以系統管理員權限執行。 對來路不明的外掛或瀏覽器來源的 URL 要特別小心。
  • 一般權限的工具（AutoHotkey、巨集軟體等）無法對 OBS 送出按鍵或視窗操作。 快速鍵建議透過 obs-websocket 操作（Stream Deck 等）。
  • 從 OBS 開啟的檔案・啟動的程式也會變成系統管理員權限。

為什麼無法拖放

Windows 有一種叫做 UIPI（User Interface Privilege Isolation）的機制， 會阻擋權限較低的程序傳給權限較高的程序的視窗訊息。 檔案總管是一般權限，OBS 是系統管理員權限，因此拖放操作（OLE D&D／WM_DROPFILES） 無法傳到 OBS，游標會變成「禁止」。不建議以系統管理員身分執行檔案總管。

DDLauncher 以一般權限執行，所以能接收來自檔案總管的拖放。 收到的檔案路徑會透過 obs-websocket（localhost 連線）傳給 OBS。 網路連線不受 UIPI 限制，即使權限不同也能安全傳到 OBS。

※ 若以系統管理員身分執行啟動器本身，基於相同原因無法使用 D&D（標題列會顯示 ⚠ADMIN）。

給實況主的使用建議

  • 遊戲 → 遊戲擷取（模式建議「擷取特定視窗」。 「擷取任何全螢幕應用程式」有時會拍到 Alt+Tab 切過去的遊戲以外的東西）
  • 遊戲擷取是黑的 → 改用視窗擷取（方式：Windows 10 (1903 以上)）。 還是不行就用顯示器擷取
  • 留言檢視器・瀏覽器・工具 → 視窗擷取（方式 Windows 10 (1903 以上) 較穩定）
  • 顯示器擷取是最後手段。通知、Discord、密碼輸入等整個桌面都會被拍到，小心直播事故
  • 遊戲擷取即使視窗疊在上面也不會拍到，直播中操作其他應用程式也安全。 視窗擷取也一樣，但要注意對象最小化時影像會停住（用本啟動器「最小化啟動」的應用程式，擷取前請先還原一次）

黑畫面等注意事項

  • 筆電（兩個 GPU）：OBS 與擷取對象在不同的 GPU 上執行時，顯示器擷取會變黑。 請在 Windows 的「圖形設定」中讓 OBS 使用相同的 GPU。
  • 瀏覽器中的 DRM 影片（串流服務等）會因保護而變黑。關閉瀏覽器的硬體加速 有時能拍到，但也要注意權利上的問題。
  • 以系統管理員權限執行的應用程式，用一般權限的 OBS 做視窗擷取時會變黑／不會出現在清單中。 → 這是以系統管理員身分執行 OBS 的主要理由之一。
  • 遊戲擷取是黑的時候：啟用「使用反作弊相容性掛鉤」，或改用顯示器擷取。
  • 以最小化狀態啟動的視窗，在視窗擷取中可能「最小化時拍不到」。 啟動後請先還原成原本的大小一次。

啟動序列

  • 依設定中的順序，在「上一個應用程式啟動後 等待秒數 後」啟動。已在執行中的應用程式不會重複啟動。
  • DAW 或 VB-Audio（VoiceMeeter 等）放在最後並把等待時間拉長，比較能避免搶奪音訊裝置。
  • 「最小化啟動」只是把視窗顯示方式指定為最小化。有些應用程式會忽略 （OBS 使用參數 --minimize-to-tray 比較可靠）。
  • 「判斷用 exe 名稱」用來判斷是否執行中。若是啟動器類型的應用程式（啟動後由另一個 exe 成為本體），請填入本體的 exe 名稱。

指定啟動後的螢幕

  • 在設定的「啟動後移至的螢幕」欄選擇後，啟動後最多等待 30 秒讓視窗出現，再移到該螢幕（保持螢幕內的相對位置與最小化／最大化狀態）。
  • 以系統管理員權限啟動的應用程式無法移動（因 UIPI，一般權限的啟動器無法操作）。 OBS 等會自己記住上次的位置，只要手動放好一次，下次就會出現在那裡。
  • 啟動後會先顯示啟動畫面的應用程式，主視窗可能不會被移動。

連接埠管理

  • 登錄 OBS WebSocket（4455）或留言檢視器・連動工具使用的連接埠，即可確認使用狀況。
  • 空閒（灰）／使用中（綠：由預期程序使用）／衝突（紅：由非預期程序使用・重複登錄）。
  • 在「預期程序」填入 exe 名稱（例：obs64.exe），其他應用程式佔用同一個連接埠時就會顯示為衝突。
  • 「釋放」會結束正在使用該連接埠的程序。系統管理員權限的程序無法結束。 發生衝突時，基本做法是在其中一個應用程式的設定中更改連接埠號碼。

OBS 端的設定

在 OBS 選單「工具」→「WebSocket 伺服器設定」中啟用，並把連接埠與密碼 填入 DDLauncher 設定的「一般 / OBS」。
