表示の見方

  • 枠・ランプ 灰: 停止 / 未設定
  • 緑: 起動中（通常権限）
  • 橙: 起動中（管理者権限）
  • 赤: 「管理者で起動」指定なのに通常権限で動いている
  • OBS タイルの縁: 水色 = 配信していない / 赤 = 配信中 / 紫 = 録画のみ。中段の数字は通信量
  • オレンジに点滅しているタイル: 起動シーケンスで次に起動するアプリ
  • タイル右上: ADMIN / USER / STANDBY（停止）/ NO PATH（未設定）
  • GROUP（縦に並べる。LINEAR は未実装）: ホイール / ▲▼ で輪を回す。同じカテゴリのアプリは重なり、マウスを乗せると横に出る。Shift+ホイール / チルトで段の中を横に回す

表示モード（LINEAR / GROUP）、横・縦の上限、シーケンス完了後の動作（最小化 / 隠す）は設定の「全般」で変更できます。 隠したランチャーはタスクトレイのアイコンから戻せます。

普段の表示は「アイコンのみ（マウスを乗せると展開）」と「常に展開」から選べます（設定の「全般」、または余白の右クリックメニュー）。 D&D モード中と起動シーケンス中は開いたままにします。

大きさはランチャー上で Ctrl+マウスホイール、または設定の「大きさ」で変更できます。

アイコン左クリック = 起動（起動中なら何もしない）／右クリック = 権限を選んで起動。
ランチャー余白を右クリックでメニュー（配置・シーケンス・設定・終了）。

OBS を管理者権限で起動するメリット

  • OBS が自分の GPU 優先度を上げられるため、ゲームで GPU 負荷が高いときの 「レンダリングラグ / エンコードラグ」が出にくくなる。
  • 管理者権限で動いているゲーム・アプリをゲームキャプチャ / ウィンドウキャプチャできる。
  • 一部のアンチチート付きゲームで、管理者権限でないとキャプチャできないことがある。

デメリット

  • エクスプローラーからのドラッグ＆ドロップができなくなる。（下記）
  • 起動のたびに UAC 確認が出る。スタートアップから起動した場合はログオン直後に UAC が出る。
  • OBS 内のブラウザソース・プラグイン・スクリプトもすべて管理者権限で動く。 出所の怪しいプラグインやブラウザソースの URL には特に注意。
  • 通常権限のツール（AutoHotkey、マクロソフト等）から OBS へキー入力やウィンドウ操作が届かない。 ホットキーは obs-websocket 経由の操作（Stream Deck 等）を推奨。
  • OBS から開いたファイル・起動したプログラムも管理者権限になる。

なぜドラッグ＆ドロップができなくなるのか

Windows には UIPI（User Interface Privilege Isolation）という仕組みがあり、 権限の低いプロセスから高いプロセスへのウィンドウメッセージを遮断します。 エクスプローラーは通常権限、OBS は管理者権限なので、ドロップ操作（OLE D&D / WM_DROPFILES）が OBS に届かず「禁止」カーソルになります。エクスプローラーを管理者で動かす方法は推奨されません。

DDLauncher は通常権限で動くため、エクスプローラーからのドロップを受け取れます。 受け取ったファイルパスは obs-websocket（localhost の通信）で OBS に送られます。 ネットワーク通信は UIPI の対象外なので、権限差があっても安全に OBS へ伝わります。

※ ランチャー自体を管理者で起動すると同じ理由で D&D が使えません（ヘッダに ⚠ADMIN 表示）。

配信者向けの使い分け

  • ゲーム → ゲームキャプチャ（モードは「特定のウィンドウをキャプチャ」推奨。 「フルスクリーンアプリケーションをキャプチャ」は Alt+Tab 先のゲーム以外を映してしまうことがある）
  • ゲームキャプチャが黒い → ウィンドウキャプチャ（方式: Windows 10 (1903以降)）に切り替える。 それでも駄目なら画面キャプチャ
  • コメントビューア・ブラウザ・ツール → ウィンドウキャプチャ（方式: Windows 10 (1903以降) が安定）
  • 画面キャプチャは最終手段。通知・Discord・パスワード入力などデスクトップの全てが映るので、配信事故に注意
  • ゲームキャプチャはウィンドウを重ねても映らないため、配信中に他アプリを操作しても安全。 ウィンドウキャプチャも同様だが、対象を最小化すると映像が止まる点に注意（このランチャーの「最小化で起動」を使ったアプリは、キャプチャ前に一度元に戻す）

黒画面などの注意点

  • ノート PC（GPU 2 つ）: OBS とキャプチャ対象が別 GPU で動くと画面キャプチャが黒くなる。 Windows の「グラフィックの設定」で OBS の GPU を合わせる。
  • ブラウザの DRM 動画（配信サービス等）は保護により黒くなる。ブラウザのハードウェアアクセラレーションを 切ると映る場合があるが、権利上の問題にも注意。
  • 管理者権限で動くアプリを通常権限の OBS でウィンドウキャプチャすると黒くなる / 一覧に出ない。 → OBS を管理者で動かす主な理由の 1 つ。
  • ゲームキャプチャが黒い場合: 「アンチチート互換フック」を有効化、または画面キャプチャに切替。
  • 最小化状態で起動したウィンドウは、ウィンドウキャプチャ側で「最小化中は映らない」ことがある。 起動後に一度元のサイズに戻しておく。

起動シーケンス

  • 設定の並び順に、「前のアプリを起動してから 遅延秒 後」に起動。既に起動中のアプリは二重起動しない。
  • DAW や VB-Audio（VoiceMeeter 等）は最後に置き、遅延を長めにするとオーディオデバイスの取り合いを避けやすい。
  • 「最小化で起動」はウィンドウ表示指定を最小化で渡すだけ。無視するアプリもある （OBS は引数 --minimize-to-tray の方が確実）。
  • 「起動判定の exe 名」は起動判定用。ランチャー的なアプリ（起動後に別 exe が本体になるもの）は本体の exe 名を入れる。

起動モニタの指定

  • 設定の「起動後に移すモニタ」列で選ぶと、起動後にウィンドウが現れるのを最大 30 秒待ち、そのモニタへ移します（モニタ内の相対位置・最小化/最大化は維持）。
  • 管理者権限で起動したアプリは移動できません（UIPI により通常権限のランチャーから操作不可）。 OBS などは自分で前回位置を覚えているので、一度手で置いておけば次回からそこに出ます。
  • 起動直後にスプラッシュ画面を出すアプリは、本体ウィンドウが移らないことがあります。

ポート管理

  • OBS WebSocket（4455）やコメントビューア・連携ツールが使うポートを登録しておくと、使用状況を確認できます。
  • 空き（灰）/ 使用中（緑: 想定プロセスが使用）/ 衝突（赤: 想定外のプロセスが使用・重複登録）。
  • 「想定プロセス」に exe 名（例: obs64.exe）を入れると、別のアプリが同じポートを掴んでいるときに衝突として表示されます。
  • 「解放」は、そのポートを使っているプロセスを終了します。管理者権限のプロセスは終了できません。 衝突時は、どちらかのアプリの設定でポート番号を変えるのが基本です。

OBS 側の設定

OBS メニュー「ツール」→「WebSocket サーバー設定」で有効化し、ポートとパスワードを DDLauncher の設定「全般 / OBS」に入力してください。
