표시 보는 법

  • 테두리·램프 회색: 정지 / 미설정
  • 초록: 실행 중 (일반 권한)
  • 주황: 실행 중 (관리자 권한)
  • 빨강: "관리자로 실행"으로 지정했는데 일반 권한으로 실행 중
  • OBS 타일 테두리: 하늘색 = 방송 안 함 / 빨강 = 방송 중 / 보라 = 녹화만. 가운데 숫자는 전송량
  • 주황색으로 깜빡이는 타일: 실행 시퀀스에서 다음에 실행할 앱
  • 타일 오른쪽 위: ADMIN / USER / STANDBY (정지) / NO PATH (미설정)
  • GROUP (세로로 늘어놓기. LINEAR는 아직 미구현): 휠 / ▲▼로 고리를 돌립니다. 같은 카테고리의 앱은 겹쳐지고, 마우스를 올리면 옆으로 펼쳐집니다. Shift+휠 / 틸트로 줄 안을 옆으로 돌립니다

표시 모드 (LINEAR / GROUP), 가로·세로 상한, 시퀀스 완료 후 동작 (최소화 / 숨기기)은 설정의 "일반"에서 바꿀 수 있습니다. 숨긴 런처는 작업 표시줄 트레이 아이콘에서 되돌릴 수 있습니다.

평소 표시는 "아이콘만 (마우스를 올리면 펼치기)"과 "항상 펼치기" 중에서 고를 수 있습니다 (설정의 "일반", 또는 여백 우클릭 메뉴). D&D 모드 중과 실행 시퀀스 중에는 펼친 상태를 유지합니다.

크기는 런처 위에서 Ctrl+마우스 휠, 또는 설정의 "크기"로 바꿀 수 있습니다.

아이콘 좌클릭 = 실행 (이미 실행 중이면 아무것도 안 함) / 우클릭 = 권한을 골라 실행.
런처 여백을 우클릭하면 메뉴 (위치·시퀀스·설정·종료).

OBS를 관리자 권한으로 실행하는 장점

  • OBS가 자기 GPU 우선순위를 올릴 수 있어, 게임으로 GPU 부하가 클 때 "렌더링 지연 / 인코딩 지연"이 잘 생기지 않습니다.
  • 관리자 권한으로 실행 중인 게임·앱을 게임 캡처 / 윈도우 캡처할 수 있습니다.
  • 일부 안티치트가 있는 게임은 관리자 권한이 아니면 캡처되지 않을 수 있습니다.

단점

  • 탐색기에서 드래그 앤 드롭을 할 수 없게 됩니다. (아래 참고)
  • 실행할 때마다 UAC 확인이 나옵니다. 시작 프로그램으로 실행하면 로그인 직후 UAC가 나옵니다.
  • OBS 안의 브라우저 소스·플러그인·스크립트도 모두 관리자 권한으로 실행됩니다. 출처가 불분명한 플러그인이나 브라우저 소스 URL에 특히 주의하세요.
  • 일반 권한 도구 (AutoHotkey, 매크로 프로그램 등)에서 OBS로 키 입력이나 창 조작이 전달되지 않습니다. 단축키는 obs-websocket을 통한 조작 (Stream Deck 등)을 권장합니다.
  • OBS에서 연 파일·실행한 프로그램도 관리자 권한이 됩니다.

왜 드래그 앤 드롭을 할 수 없게 되나요

Windows에는 UIPI (User Interface Privilege Isolation)라는 구조가 있어, 권한이 낮은 프로세스에서 높은 프로세스로 가는 창 메시지를 차단합니다. 탐색기는 일반 권한, OBS는 관리자 권한이므로 드롭 조작 (OLE D&D / WM_DROPFILES)이 OBS에 닿지 않고 "금지" 커서가 됩니다. 탐색기를 관리자로 실행하는 방법은 권장하지 않습니다.

DDLauncher는 일반 권한으로 실행되므로 탐색기에서 드롭을 받을 수 있습니다. 받은 파일 경로는 obs-websocket (localhost 통신)으로 OBS에 보냅니다. 네트워크 통신은 UIPI의 대상이 아니므로, 권한이 달라도 안전하게 OBS에 전달됩니다.

※ 런처 자체를 관리자로 실행하면 같은 이유로 D&D를 쓸 수 없습니다 (헤더에 ⚠ADMIN 표시).

방송인을 위한 구분

  • 게임 → 게임 캡처 (모드는 "특정 창 캡처" 권장. "전체 화면 응용 프로그램 캡처"는 Alt+Tab으로 넘어간 게임이 아닌 것을 비출 때가 있음)
  • 게임 캡처가 검다 → 윈도우 캡처 (방식: Windows 10 (1903 이상))로 바꿉니다. 그래도 안 되면 디스플레이 캡처
  • 채팅 뷰어·브라우저·도구 → 윈도우 캡처 (방식: Windows 10 (1903 이상)이 안정적)
  • 디스플레이 캡처는 최후의 수단. 알림·Discord·비밀번호 입력 등 데스크톱 전체가 비치므로 방송 사고에 주의
  • 게임 캡처는 창을 겹쳐도 비치지 않으므로, 방송 중에 다른 앱을 조작해도 안전합니다. 윈도우 캡처도 같지만 대상을 최소화하면 영상이 멈추는 점에 주의 (이 런처의 "최소화로 실행"을 쓴 앱은 캡처 전에 한 번 원래대로 되돌리세요)

검은 화면 등 주의할 점

  • 노트북 (GPU 2개): OBS와 캡처 대상이 다른 GPU에서 실행되면 디스플레이 캡처가 검게 됩니다. Windows의 "그래픽 설정"에서 OBS의 GPU를 맞추세요.
  • 브라우저의 DRM 영상 (스트리밍 서비스 등)은 보호 때문에 검게 됩니다. 브라우저의 하드웨어 가속을 끄면 비칠 때도 있지만, 권리상의 문제에도 주의하세요.
  • 관리자 권한으로 실행되는 앱을 일반 권한 OBS로 윈도우 캡처하면 검게 되거나 목록에 나오지 않습니다. → OBS를 관리자로 실행하는 주된 이유 중 하나.
  • 게임 캡처가 검은 경우: "안티 치트 호환 후크 사용"을 켜거나 디스플레이 캡처로 바꾸세요.
  • 최소화 상태로 실행한 창은 윈도우 캡처에서 "최소화 중에는 비치지 않는" 경우가 있습니다. 실행 후 한 번 원래 크기로 되돌려 두세요.

실행 시퀀스

  • 설정의 순서대로 "이전 앱을 실행한 뒤 대기 초 후"에 실행합니다. 이미 실행 중인 앱은 두 번 실행하지 않습니다.
  • DAW나 VB-Audio (VoiceMeeter 등)는 마지막에 두고 대기를 길게 하면 오디오 장치 쟁탈을 피하기 쉽습니다.
  • "최소화로 실행"은 창 표시를 최소화로 지정해 넘길 뿐입니다. 무시하는 앱도 있습니다 (OBS는 인수 --minimize-to-tray가 더 확실합니다).
  • "실행 판정용 exe 이름"은 실행 판정에 씁니다. 런처형 앱 (실행 후 다른 exe가 본체가 되는 것)은 본체의 exe 이름을 넣으세요.

실행할 모니터 지정

  • 설정의 "실행 후 이동할 모니터" 열에서 고르면, 실행 후 창이 나타나기를 최대 30초 기다려 그 모니터로 옮깁니다 (모니터 안의 상대 위치·최소화/최대화는 유지).
  • 관리자 권한으로 실행한 앱은 옮길 수 없습니다 (UIPI 때문에 일반 권한 런처에서 조작 불가). OBS 등은 스스로 지난 위치를 기억하므로, 한 번 손으로 놓아 두면 다음부터 거기에 나옵니다.
  • 실행 직후 스플래시 화면을 띄우는 앱은 본체 창이 옮겨지지 않을 수 있습니다.

포트 관리

  • OBS WebSocket (4455)이나 채팅 뷰어·연동 도구가 쓰는 포트를 등록해 두면 사용 상황을 확인할 수 있습니다.
  • 비어 있음 (회색) / 사용 중 (초록: 예상 프로세스가 사용) / 충돌 (빨강: 예상 밖의 프로세스가 사용·중복 등록).
  • "예상 프로세스"에 exe 이름 (예: obs64.exe)을 넣으면, 다른 앱이 같은 포트를 잡고 있을 때 충돌로 표시됩니다.
  • "해제"는 그 포트를 쓰는 프로세스를 종료합니다. 관리자 권한 프로세스는 종료할 수 없습니다. 충돌 시에는 어느 한쪽 앱의 설정에서 포트 번호를 바꾸는 것이 기본입니다.

OBS 쪽 설정

OBS 메뉴 "도구" → "WebSocket 서버 설정"에서 활성화하고, 포트와 비밀번호를 DDLauncher 설정의 "일반 / OBS"에 입력하세요.
